# harness-experiment-01

**성공 기록 참조가 다음 실행을 개선하는가** — 하네스의 '경험·스킬 축적' 축을 로컬 환경에서 시험한 기록

- **실험일**: 2026-09-02
- **대상 기능 축**: 경험·스킬 축적 / 반성(Reflexion) / 성공 궤적 재사용(ExpeL)

| 실험 | 묻는 것 | 판정 |
|---|---|---|
| **01** | 반성 기록을 참조시키면 재지시·시간이 줄어드는가 | **기각** |
| **02** | 재지시가 0인 원인이 **과업 난이도**인가 | **게이트 중단** — 추정 반증 |
| **03** | 지표를 **처리 시간**으로 바꾸면 효과가 보이는가 | **지지** |

---

## 세 실험의 관계

```
실험 01  가설 기각        원인 추정: "과업 난이도가 낮아서"
   |
실험 02  그 추정을 시험    난이도를 올려도 재지시 0  ->  추정 반증
   |                      새 결론: "지표가 작동하지 않는다"
실험 03  그 결론을 시험    지표를 처리 시간으로 교체  ->  지지
```

기각에서 멈추지 않고, **기각의 이유로 내세운 설명 자체를 다시 시험**했다.
세 실험 모두 판정선을 **시작 전에** 확정했고, 결과 확인 후 변경하지 않았다.

## 실험 03 결과 (주 결과)

### 원자료 — 모델 처리 시간(초)

A = notes 없음 / B = `notes/approach.md` 참조

| 과업 | A run-1 | A run-4 | A run-5 | B run-2 | B run-3 | B run-6 |
|---|---|---|---|---|---|---|
| ① parse-log | 48 | 93 | 74 | 27 | 40 | 48 |
| ② refactor-util | 34 | 36 | **164** | 24 | 24 | 45 |
| ③ fix-failing | 17 | 37 | 27 | 12 | 12 | 16 |
| **합계** | **99** | **166** | **265** | **63** | **76** | **109** |
| 재지시 | 0 | 0 | **2** | 0 | 0 | 0 |

### 판정선 대입 (사전 확정: 3과업 중 2종 이상에서 `B평균 < A평균`)

| 과업 | A 평균 | B 평균 | 차이 | 충족 |
|---|---|---|---|---|
| ① parse-log | 71.7s | 38.3s | -47% | ✅ |
| ② refactor-util | 78.0s | 31.0s | -60% | ✅ |
| ③ fix-failing | 27.0s | 13.3s | -51% | ✅ |

**충족 3종 / 판정선 2종 → 가설 지지**

중앙값으로도 세 과업 모두 B 가 낮다(74/36/27 vs 40/24/16). 이상치 하나가 만든 결과가 아니다.

### 설계에서 개선한 것

| # | 개선 | 무엇을 해결했나 |
|---|---|---|
| 1 | 지표를 **재지시 -> 처리 시간(초)** 으로 교체 | 바닥 효과 |
| 2 | 각 조건 **3회 반복** | 1회 측정의 우연 |
| 3 | 조건 **교대 배치**(A B B A A B) | 순서 효과 |
| 4 | 표방 논문을 Reflexion -> **ExpeL** 로 정정 | 가설과 조작의 어긋남 |
| 5 | 판정을 화면 요약이 아니라 **결과 파일 대조**로 | 요약 신뢰 문제 |

3번이 가능한 이유: `notes/approach.md` 를 실험 02 1차 기록에서 미리 뽑아뒀기 때문이다.
실험 01·02는 "2차가 항상 나중"이라 처치 효과와 순서 효과가 섞여 있었다.

### 부수 관찰

- **재지시는 A 조건에서만 발생**했다(run-5, 2회). 실험 02에서 "작동하지 않는다"던 지표에 조건을 바꾸자 값이 생겼다.
- run-5 가 틀린 항목은 `chunk_list` 반환형이고, `notes/approach.md` 에 *"chunk_list 의 반환은 중첩 리스트다"* 가 적혀 있다. **B 조건 3회는 전부 맞혔다.**
- A 조건은 작성 전 승인을 묻는 턴이 잦았고, B 조건은 바로 작성했다. **탐색 단계 생략**이 시간 차의 실체로 보인다.

## 실험 01·02 요약

### 실험 01 — 기각

| 작업 | 1차 (기록 없음) | 2차 (기록 참조) | 판정선 충족 |
|---|---|---|---|
| ① parse-log | 3분 / 승인 2 / 재지시 0 | 2분 / 승인 2 / 재지시 0 | ✅ |
| ② refactor-util | 1분 / 승인 2 / 재지시 0 | 1분 / 승인 2 / 재지시 0 | ❌ |
| ③ fix-failing | 1분 / 승인 2 / 재지시 0 | 1분 / 승인 2 / 재지시 0 | ❌ |

재지시가 양 조건 모두 0회였다. 0에서 더 줄어들 수 없어 지표가 작동하지 않았다 — 바닥 효과.

### 실험 02 — 게이트 중단

fixture 에 함정 4종을 심어 난이도를 올렸다.

| 함정 | 모델의 처리 |
|---|---|
| ERROR 아래 들여쓴 스택 트레이스 4줄 | "레벨 표시가 없는 부가 정보"라며 스스로 제외 |
| `INFO ... user reported an ERROR in the UI form` | "메시지에 단어만 있고 실제 레벨은 INFO"라며 제외 |
| 한 줄만 다른 시각 포맷 | 정규식에 두 형식을 모두 넣어 처리 |
| `median` 짝수 처리 / `percent_change` 분모 오류 | 실행 전에 읽고 원인 2개를 정확히 지목 |

**재지시는 여전히 0회.** 사전에 정한 게이트(1차 재지시 2회 미만이면 중단)에 따라 2차를 실시하지 않았다.
난이도를 올린 것이 아니라, 모델이 그 난이도를 그대로 넘겼다.

## 다음에 바꿀 조건 하나 — 하네스 일반화

실험 03의 지지 판정은 **Claude Code / Sonnet 5 조합 하나**에서의 결과다.

### [실험 04] 하네스 2종 교차

- 대상: **Claude Code (Sonnet 5)** / **OpenClaw (Gemini)** — 3과업 x 2조건 x 3반복 x 2하네스 = 36시행
- 각 하네스 **내부에서만** 비교한다. **하네스 간 절대값은 비교하지 않는다**
- 판정: 두 하네스 모두 감소 재현 -> 하네스·모델 무관 효과 / 한 쪽만 -> 원인 분리 불가로 기록
- **한계**: 하네스와 모델이 동시에 달라 원인 귀속 불가. 모델 고정에는 별도 유료 API 가 필요해 범위에서 제외
- **한계**: 표본 2종이라 "일반화"까지는 주장할 수 없다

| 실행 환경 | WSL Ubuntu 24.04 | 동일 | 동일 |

| fixture 난이도 | 평이 | **함정 4종** | 실험 02와 동일 |
| 조작 변수 | 반성 기록 참조 | fixture 난이도 | **성공 궤적 기록 참조** |

| 반복 | 1회 | 1회 | **3회** |

실험 01 실행 중 권한 모드가 auto 로 전환된 시행이 1건 발생했고, 해당 시행은 **폐기하고 폴더를 재생성한 뒤 다시 실행**했다.

### 승인 횟수 지표의 정의 근거

사전 관찰 기록 `obs-lab-observation-01.md` 에서, 화면의 *"실행해도 될까요?"* 에 두 종류가 있음을 확인했다.

| 구분 | 주체 | 우회 가능성 |
|---|---|---|
| 모델이 **말로** 묻기 | 모델 판단 (전역 `CLAUDE.md` 규칙 때문) | 규칙이 없으면 그냥 실행됨 |
| 하네스 **승인 창** | 하네스가 강제 | 뚫을 수 없음 |

본 실험이 세는 것은 **후자뿐**이다. 이 구분이 없으면 `CLAUDE.md` 규칙을 바꾸는 것만으로 지표가 움직인다.

### 실험 02·03에서 추가한 절차

1. **완료 판정 기준을 프롬프트에 적지 않는다.** 진행자만 `grading-key.md` 로 보유한다
2. **재지시 문구를 사전에 문서로 고정한다.** "무엇이 틀렸다"까지만 말하고 정답은 주지 않는다
3. **재지시 상한 5회.** 초과 시 미완료로 기록
4. **게이트.** 1차 재지시 총합 2회 미만이면 2차로 넘어가지 않는다 (실험 02)
5. **확인 질문에는 같은 재지시 문구를 그대로 다시 보낸다.** 새 정보를 주지 않는다 (실험 03에서 추가)

## 재현 방법

### 실험 03

```bash
python3 setup_exp03.py      # ~/exp03/run-1..6 생성 (조건 배치 A B B A A B)
cd ~/exp03/run-1 && claude  # Sonnet 5 / manual / effort high
```

프롬프트는 `exp03/PLAN.md`, 완료 판정과 재지시 문구는 `grading-key.md` 를 따른다.
B 조건은 각 프롬프트 앞에 `notes/approach.md 를 먼저 읽고,` 를 붙인다.

> `setup_exp03.py` 는 계획서와 `notes/` 를 `~/exp03-control/` 로 분리해야 한다.
> `~/exp03/` 아래에 두면 A 조건 세션이 상위 폴더에서 정답을 볼 수 있다.

### 실험 02

```bash
python3 setup_exp02.py
cd ~/exp02/trial-1 && claude
```

### 실험 01

```bash
cp -r fixture trial-1-repro
cp -r fixture trial-2-repro && cp notes/reflection.md trial-2-repro/
```

### 공통 주의

- 권한 모드는 **manual** 로 고정한다. auto 는 승인 횟수를 조작 변수와 무관하게 바꾼다
- thinking effort 를 모든 run 에서 동일하게 유지한다. 다르면 처리 시간이 통째로 흔들린다
- 완료 조건을 프롬프트에 넣지 않는다. 넣으면 재지시가 발생하지 않는다
- fixture 에 없는 추가 과업을 넣지 않는다
