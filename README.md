# harness-experiment-01

**성공 기록 참조가 다음 실행을 개선하는가** — 하네스의 '경험·스킬 축적' 축을 로컬 환경에서 시험한 기록

- **실험일**: 2026-09-02
- **대상 기능 축**: 경험·스킬 축적 / 반성(Reflexion)
- **실험 01 판정**: **가설 기각**
- **실험 02 판정**: **게이트에서 중단** — 실험 01의 기각 원인 추정을 **반증**

---

## 한 장 요약

| | 실험 01 | 실험 02 (후속) |
|---|---|---|
| **묻는 것** | 반성 기록을 참조시키면 재지시·시간이 줄어드는가 | 재지시가 0인 원인이 **과업 난이도**인가 |
| **조작 변수** | 반성 기록 참조 여부 **하나** | fixture 난이도 **하나** (판정선·지표·환경은 실험 01과 동일) |
| **사전 판정선** | 3종 중 **2종 이상** 감소 → 지지 | 동일 + **게이트**: 1차 재지시 총합 2회 미만이면 중단 |
| **결과** | 1종만 충족 → **기각** | 재지시 **0회** → **중단** |
| **얻은 것** | 바닥 효과로 지표가 작동하지 않았다 | 그 원인은 난이도가 아니었다 |

판정선과 게이트는 **실험 시작 전에** 확정했고, 결과 확인 후 변경하지 않았다.

## 왜 기각됐고, 왜 그 설명이 다시 틀렸는가

### 실험 01의 설명

**재지시가 양 조건 모두 0회였다.** 0에서 더 줄어들 수 없으므로 이 지표로는 차이를 관찰할 수 없었다 — 바닥 효과(floor effect).

당시 원인을 **과업 난이도**로 추정했다. 그러나 이것은 관찰이 아니라 **추정**이었다.

### 실험 02가 그 추정을 시험했다

fixture에 함정 4종을 심어 난이도를 올렸다.

| 함정 | 모델의 처리 |
|---|---|
| ERROR 아래 들여쓴 스택 트레이스 4줄 | "레벨 표시가 없는 부가 정보"라며 스스로 제외 |
| `INFO ... user reported an ERROR in the UI form` | "메시지에 단어만 있고 실제 레벨은 INFO"라며 제외 |
| 한 줄만 다른 시각 포맷 `28/Aug/2026:...` | 정규식에 두 형식을 모두 넣어 처리 |
| `median` 짝수 처리 / `percent_change` 분모 오류 | 실행 전에 읽고 원인 2개를 정확히 지목 |

**재지시는 여전히 0회였다.** 난이도를 올린 것이 아니라, 모델이 그 난이도를 그대로 넘겼다.

### 그래서 진짜 원인

> **이 조합(Claude Code + Sonnet 5 + 단일 파일 수십 줄 과업)에서는
> "재지시 횟수"라는 지표 자체가 작동하지 않는다.**

재지시는 모델이 틀려야 발생한다. 틀리지 않으면 값은 영원히 0이다.
바꿔야 할 것은 난이도가 아니라 **지표** 또는 **과업의 규모**다.

소요 시간도 같은 문제를 겪었다. 실험 02 과업 ②는 1차에서 이미 **0분**이라 줄어들 여지가 물리적으로 없었다.

## 다음 실험에서 바꿀 조건

실험 02가 "난이도 상향" 안을 반증했으므로, 방향을 **지표와 규모**로 옮긴다.

### [실험 03] 타당도 — 하네스 1종 고정

- **지표 교체**: 재지시 횟수 대신 → 모델 처리 시간(초) / 도구 호출 횟수 / 탐색 단계 생략 여부
- **과업 규모 확대**: 단일 파일이 아니라 **여러 파일에 걸친 과업**. 모델이 한 번에 맞히지 못하는 규모여야 재지시가 존재할 수 있다
- 각 조건 **3회 이상** 반복, 초 단위 기록
- 판정선은 실험 전 확정
- **선행 조건**: 1차에서 재지시가 또 0이면 재지시 지표를 폐기하고 처리 시간으로 전환

### [실험 04] 일반화 — 하네스 2종 교차

- 대상: **Claude Code (Sonnet 5)** / **OpenClaw (Gemini)** — 3과업 x 2조건 x 3반복 x 2하네스 = 36시행
- 각 하네스 **내부에서만** 기록 참조 유무를 비교. **하네스 간 절대값은 비교하지 않는다**
- 판정: 두 하네스 모두 감소 재현 → 하네스·모델 무관 효과 / 한 쪽만 → 원인 분리 불가로 기록
- **한계**: 하네스와 모델이 동시에 다르므로 원인 귀속 불가. 모델 고정에는 별도 유료 API가 필요해 범위에서 제외
- **한계**: 표본 2종이라 "일반화"까지는 주장할 수 없다

```
타당도(실험 03)  ->  일반화(실험 04)
```

바닥 효과가 남은 상태로 하네스를 늘리면 고장난 자를 두 개로 늘리는 것과 같다.

### 사후에 발견한 지표 후보 (판정에는 사용하지 않음)

실험 01에서 화면에 모델 처리 시간이 초 단위로 남아 있었고, 세 작업 모두 감소했다(59s → 43s, -27%).
그러나 **결과를 본 뒤에 인지한 지표**이므로 판정에 쓰지 않았다.
사후에 유리한 지표로 판정선을 갈아끼우면 실험이 무효가 된다.

## 관찰 조건 (fixture)

| 항목 | 실험 01 | 실험 02 |
|---|---|---|
| 하네스 | Claude Code CLI **v2.1.258** | 동일 |
| 모델 | **Sonnet 5** | 동일 |
| 권한 모드 | **manual mode** | 동일 |
| 실행 환경 | WSL Ubuntu 24.04 | 동일 |
| 테스트 러너 | pytest **7.4.4** | 동일 |
| 프롬프트 | 3종 문장 고정. 2차에만 `reflection.md 를 먼저 읽고,` 추가 | 동일. 단 **완료 조건을 프롬프트에서 분리** |
| fixture 난이도 | 평이 | **함정 4종 삽입** |

실험 01 실행 중 권한 모드가 auto로 전환된 시행이 1건 발생했고, 해당 시행은 **폐기하고 폴더를 재생성한 뒤 다시 실행**했다 (보고서 4절).

### 승인 횟수 지표의 정의 근거

사전 관찰 기록 `obs-lab-observation-01.md` 에서, 화면의 *"실행해도 될까요?"* 에 두 종류가 있음을 확인했다.

| 구분 | 주체 | 우회 가능성 |
|---|---|---|
| 모델이 **말로** 묻기 | 모델 판단 (전역 `CLAUDE.md` 규칙 때문) | 규칙이 없으면 그냥 실행됨 |
| 하네스 **승인 창** | 하네스가 강제 | 뚫을 수 없음 |

본 실험이 세는 것은 **후자뿐**이다. 이 구분이 없으면 `CLAUDE.md` 규칙을 바꾸는 것만으로 지표가 움직인다.
같은 관찰에서 auto mode일 때는 쓰기 작업에도 승인 창이 뜨지 않았고, 이것이 위 오염 사고가 측정값을 바꾼 이유다.

### 실험 02에서 추가한 절차

1. **완료 판정 기준을 프롬프트에 적지 않는다.** 진행자만 `grading-key.md` 로 보유한다
2. **재지시 문구를 사전에 문서로 고정한다.** "무엇이 틀렸다"까지만 말하고 정답은 주지 않는다
3. **재지시 상한 5회.** 초과 시 미완료로 기록하고 다음 과업으로
4. **게이트.** 1차 재지시 총합 2회 미만이면 2차로 넘어가지 않는다

## 재현 방법

### 실험 01

```bash
cp -r fixture trial-1-repro
# 해당 폴더에서 하네스 실행 후 아래 3문장을 순서대로 입력
#   sample.log 에서 ERROR 줄만 골라 시각과 메시지를 표로 출력하는 parse.py 를 만들어 줘
#   util.py 의 함수 3개에 타입 힌트와 독스트링을 추가해 줘
#   test_me.py 가 전부 통과하도록 calc.py 를 고쳐 줘. test_me.py 는 수정하지 마

cp -r fixture trial-2-repro && cp notes/reflection.md trial-2-repro/
# 같은 3문장 앞에 "reflection.md 를 먼저 읽고, " 를 붙여 입력
```

완료 판정: parse-log ERROR **3건** / refactor-util 함수 **3개** / fix-failing **5 passed**

### 실험 02

```bash
python3 setup_exp02.py          # ~/exp02/{fixtures,trial-1} 생성
cd ~/exp02/trial-1 && claude    # Sonnet 5 / manual mode 확인
```

프롬프트는 `prompts.md`, 완료 판정과 재지시 문구는 `grading-key.md` 를 따른다.
**완료 조건을 프롬프트에 넣지 않는 것이 핵심**이다. 넣으면 재지시가 발생하지 않는다.

### 공통 주의

- 권한 모드는 **manual** 로 고정한다. auto는 승인 횟수를 조작 변수와 무관하게 바꾼다
- 승인 선택지는 항상 **1번(Yes)** 만 고른다
- fixture에 없는 추가 과업을 넣지 않는다
